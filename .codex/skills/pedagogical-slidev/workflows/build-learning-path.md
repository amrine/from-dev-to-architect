# Workflow: Build Learning Path

## Objective

Convert the knowledge map into observable learning outcomes, acceptable
evidence, and a progression that moves from familiar development knowledge to
architecture judgment.

## Design basis

Use backward design and constructive alignment:

```text
outcome -> evidence of achievement -> learning activity -> teaching material
```

For complex professional skills, use a whole-task progression inspired by
4C/ID:

```text
whole task with support
  -> worked example
  -> partially completed task
  -> independent task
  -> transfer variation
```

## Procedure

1. Identify the learner's current knowledge and the performance gap.
2. State one to five essential understandings for the target scope.
3. Write observable objectives with this shape:

   ```text
   learner + action verb + context + condition + success criterion
   ```

4. Define acceptable evidence before choosing slides. Distinguish behavior,
   evidence, and mechanism.
5. Identify prerequisites and introduce only the vocabulary needed at each step.
6. Order concepts by dependency and cognitive load, not by source-file order.
7. Add guided practice, prediction, explanation, or retrieval when the objective
   requires more than recognition.
8. Plan spaced reactivation of important concepts across weeks when the deck is
   cumulative.
9. Define one bounded transfer question to test whether the learner can adapt
   the reasoning to a changed constraint.

## Alignment record

Every objective must map to:

```text
objective -> evidence -> activity -> slide(s) -> validation
```

Remove content that has no objective or move it to optional further reading.

## Outputs

- learner and performance-gap statement;
- objective list;
- evidence and activity map;
- prerequisite and vocabulary order;
- scaffold plan;
- retrieval and transfer plan;
- approved learning path.

Stop and request validation before generation when the scope is a full deck or
major week update and the user expects checkpointed work.
